# 다음 구현 계획

## 목표

실시간 데이터를 기준으로 전략이 진입·청산을 결정하고, 같은 로직을 과거 데이터와
paper에서 재현할 수 있는 상태를 만든다. 수익률 목표·일 거래 횟수는 미리 약속하지 않는다.
수십 분~수 시간 보유, 마감된 15분/1시간봉 판단을 초기 연구 후보로 제안한다.
시간 주기는 아직 확정한 전략 파라미터가 아니며, 성과에 따라 폐기 가능해야 한다.
사용자가 선택한 연구 방향은 **박스권 하단 매수·상단 청산·하단 이탈 손절**이다.
LLM이 과거 캔들에서 박스권 유효성과 진입 후보를 판단하는 변형을 연구하되,
규칙만 사용하는 비교 전략과 분리하고 응답 검증·유효기간·독립 위험 한도를 둔다.
현재는 이 전략도 LLM 연결도 구현되지 않았다.

## M0 — 회계·관측·재현 기반 (즉시 우선)

- monotonic 경과 시간과 exchange/receipt wall time 분리, 데이터 지연 p50/p95/p99 및 갭 기록.
- 일일 equity 기준과 보수적 손실 제한을 분리. 자정 데이터 부재/재시작 시 기준 정책 정의.
- 영속 위험 차단, append-only 주문 전이, 실행 ID·설정·코드 버전·신호 근거 저장.
- raw event replay에 연결/단절·heartbeat·순서를 포함해 결정적인 결과 재현.
- 주문/체결 데이터는 소실 금지. 시장 이벤트 저장은 측정 후 bounded queue와 별도 writer로 분리.

완료: 같은 입력과 설정의 replay 결과가 같고, 시계 변경·디스크 장애·날짜 변경·재시작에서
위험 기준이 초기화되거나 중복 체결이 발생하지 않음. 유효하지 않은 데이터 구간을 식별할 수 있음.

## M1 — 캔들 + 전략 + 위험 + 최소 비용 백테스트

- candle 모듈: 과거 OHLCV 확보, UTC 정렬, 누락 검증, 마감된 15분/1시간봉만 노출.
- strategy 모듈: HOLD/ENTER/EXIT 신호와 근거를 구조화. 첫 후보는 박스권 평균회귀.
  마감된 과거 캔들만으로 박스 경계를 계산하고 하단 진입·상단 청산·이탈 손절·시간 청산을 정의.
  진입 후 손절선을 불리하게 넓히지 않고, 박스 이탈 시 무효화·재진입 대기 정책을 둔다.
  탐색한 파라미터와 실패 실험도 기록한다.
- risk 모듈: 손절 거리·비용에 따른 수량, 최대 노출, SL/TP·시간 청산·일일 차단을 구현.
- backtest 모듈: 동일 전략/위험 인터페이스 사용. 다음 가능한 가격의 체결, fee/spread/slippage,
  funding 이력, 데이터 수준에 따른 체결 불확실성 처리. OHLC만으로 TP/SL 순서를 유리하게 결정 금지.
- analytics: 순기대값, 평균 손익, 최대 낙폭, 노출 시간, 거래 수, 국면별 성과, 비용 민감도.

완료: 미래 데이터 미노출, 다음 봉/틱 체결, 같은 봉 TP·SL 충돌 처리 테스트 통과.
거래하지 않는 기준 및 비교 전략과 동일 위험 조건으로 결과 보고. 성과가 없으면 명시적으로 기록.
기존 paper engine은 1배 long-only 회계이므로 실제 선물 마진 성과와 동일하다고 표시하지 않는다.

## M2 — 전략 기반 paper 운영

- exercise 명령과 별도의 전략 실행 모드. 전략 판단 주기와 실시간 위험 감시를 분리.
- 실제 최소 주문 금액·수량 단위 검증, stale 상태, 전략 준비 시간, 청산 재시도 간격을 처리.
- 장시간 수집/운영과 장애 주입. 주문 대기 중 disconnect, partial fill 후 종료, 재시작 복원.
- backtest/paper 차이를 가격·지연·체결 비용 항목으로 설명하고 실행 보고서 저장.

완료: 수동 시간 매매가 아니라 신호로 주문이 발생하고, 모든 주문의 근거를 추적 가능.
기간 하나나 거래 수 하나를 충족했다고 수익성을 인정하지 않음.

## M3 — Testnet 실행 어댑터

M0 기반이 갖춰지면 전략 연구와 별도 작업으로 개발 가능하다.

- 비밀키 관리, 계좌/포지션 조회, 거래 규칙 검증, 인증·서명, 주문·취소, 사용자 체결 이벤트.
- timeout → UNKNOWN → 조회/이벤트 대조, 누적 체결량 기준 중복 방지.
- 재시작 reconciliation, 보호 주문·긴급 청산, rate limit, 장애 중 신규 진입 차단.
- paper/testnet/live 모드 분리. live는 별도 검증 전 비활성 상태 유지.

완료: 응답 유실·중복 이벤트·취소 경합·rate limit·프로세스 재시작에서 상태가 수렴.
Testnet 체결 결과는 전략 수익성 증거로 사용하지 않는다.

## M4 — ML 비교 실험

baseline과 데이터 품질이 검증된 뒤 Logistic Regression / 작은 트리 모델로 후보 거래 필터 실험.
TP/SL/timeout 결과를 구분하고 비용 후 손익을 평가. 시간순 walk-forward, 중첩 라벨 purge,
train-only 전처리, calibration, 미사용 최종 평가 구간, AI 없는 모델과 비교.
LLM의 박스권/진입 후보 판단은 별도 실험으로 비교한다. 응답은 구조화된 가격·조건·유효기간으로
검증하고 지연·형식 오류 시 신규 진입을 보류한다. 기존 포지션의 손절은 LLM 응답을 기다리지 않는다.
LLM의 자신감이나 과거 승률 주장을 검증된 확률로 취급하지 않는다. 입력·응답·모델/프롬프트 버전과
판단 시각을 기록하고 미래 데이터/모델의 과거 사건 지식에 따른 평가 오염도 고려한다.
뉴스/운영 로그 분석은 비동기 보조 기능으로 확장 가능하다.

완료: 같은 위험 예산에서 비용 후 성과와 불확실성을 보고하고 개선이 없으면 AI를 채택하지 않음.

## M5 — 제한적 실거래 검증

위 단계의 검증 근거와 별도 실행 결정을 전제로, 제한된 위험 예산에서 paper/실제 체결 차이를 확인.
성능·손실·지연 한도 이탈 시 중단 조건을 먼저 정의. 고레버리지, 여러 전략·종목 확장은 후순위.
