# 관리자 관점 검토 — 2026-09-28

## 후속 상태 — 2026-09-29

아래 표는 2026-09-28 검토 당시의 기록이다. 이후 CLI/runtime/demo 경계를 분리하고
monotonic 시계 및 초기 지연/연결 계측을 구현했다. 해당 두 항목은 부분 해결 상태이며,
정확한 데이터 갭/주문 이력/일일 회계/독립 Risk Engine은 여전히 남아 있다.
최신 내용은 [architecture.md](architecture.md), [metrics.md](metrics.md)를 참조한다.

## 판정

현재는 단일 종목 공개 데이터 수집과 long-only 가상 주문의 초기 프로토타입이다.
데이터 수집·회계·실행 흐름의 실험에는 사용 가능하다. 전략 성과 검증과 실거래는 승인할 수 없는 상태다.
‘20개 테스트 통과’를 전체 시스템의 안전성 검증으로 해석했던 표현은 범위가 지나치게 넓었다.
코드·설정·테스트·README·설계/검증 문서를 직접 대조하고 실패 재현 테스트를 작성했다.
이번 검토는 로컬 구현 검토이며 외부 API 규격을 새로 재검증한 작업은 아니다.

## 장점

- 실주문 어댑터 자체가 없으며, 기본 모드는 관찰만 한다.
- Decimal 회계, 계좌/주문 결과의 원자적 커밋, 고유 주문 ID와 단일 DB 잠금이 있다.
- 원본 이벤트를 보존하고 이벤트 시각과 수신 시각을 구분한다.
- 불리한 편도 슬리피지·수수료, 제한된 호가 유동성, 미체결 잔량 취소를 모델링한다.
- 재시작 시 가상 주문을 무작정 재전송하지 않는다.

## 이번에 재현하고 수정한 결함

| 심각도 | 위치 | 수정 전 재현 | 수정 |
|---|---|---|---|
| 높음: 위험 검사 누락 | paper.py | 전날 매수 → 다음 날 20 USDT 이상 손실 청산 → 신규 매수에서 일일 기준이 초기화돼 진입 허용 | 모든 step의 시작에서 날짜 기준 갱신. 매도 전 기준 보존. DB 재개방 후 재진입 차단까지 검증 |
| 높음: 청산 가용성 | paper.py, market.py, cli.py | public 호가는 정상이지만 trade/mark 연결이 끊기면 reduce-only 매도도 거절 | 진입 건강 상태와 체결 가능한 호가 상태를 분리. 청산은 최신 public 호가 필요 |
| 중간: 장애 오분류 | collector.py | 내부 콜백 OSError가 네트워크 오류로 처리돼 연결과 콜백을 8회 반복 | 메시지 처리 오류를 치명적 오류로 감싸 전파. 네트워크 재시도와 분리 |

첫 검증에서 새 테스트 4개 중 3개가 위 결함으로 실패했고, 수정 후 기존 20개와 함께
24개가 통과했다. 이후 close-position CLI 통합 검증 1개를 추가해 최종 25개가 통과했다. 최초 추가 테스트의 나머지 1개는 오래된 호가에서 청산을 허용하지 않는 경계 검증이다.
기존 재시작 테스트도 같은 연결에서 객체만 재생성하는 대신 DB를 닫고 다시 열도록 강화했다.
OS 프로세스 강제 종료에 대한 crash-injection 테스트까지 수행한 것은 아니다.

## 남은 문제와 우선순위

| 우선순위 | 내용 | 영향 / 완료 방향 |
|---|---|---|
| P0: 실거래 전 필수 | 실제 계좌/주문/체결 reconciliation, UNKNOWN 주문, 보호 주문, stop/kill 경합 없음 | live 활성화 금지. Testnet 장애 주입 검증 후 별도 판단 |
| P1 | 간이 일일 손실 검사는 자정 equity 기준이 아니며 한도 도달 상태가 고정되지 않음 | 보수적 이월 손익과 일일 성과를 분리하고 영속 차단·복구 정책 정의 |
| P1 | SL/TP, 거래당 위험 sizing, 연속 손실/변동성 제한 없음 | 독립 Risk Engine과 수동/자동 청산 정책 필요 |
| P1 | 주문 지연·freshness가 wall clock 기준 | 시계 보정으로 주문 도착 시점/데이터 나이가 왜곡될 수 있음. 로컬 경과 시간은 monotonic으로 전환 |
| P1 | 데이터 갭·수신 지연·디스크 지연·재접속 이력 측정 없음 | 유효 데이터 구간을 표시하고 재현 가능한 quality report 필요 |
| P1 | 이벤트마다 동기 SQLite FULL 커밋 | 이벤트 루프 지연 가능. 먼저 처리량/지연을 계측하고 bounded queue/writer 설계, overflow 시 fail-closed |
| P1 | 주문 상태를 덮어쓰고 설정/실행 버전·신호 원인을 저장하지 않음 | append-only 주문 전이·run metadata·signal log로 거래 근거 재현 |
| P1 | replay, candle, 전략 인터페이스, 비용 backtest 없음 | 수익성 판정 자체가 불가능. roadmap의 다음 핵심 목표 |
| P2 | 체결 모델에 거래소 수량/가격 필터, maker queue, funding, 시장 충격 없음 | 매우 작은 가상 주문의 성공을 실제 주문 가능성으로 해석 금지 |
| P2 | 상위 20단계 스냅샷을 새 유동성으로 취급 | 체결 낙관 편향 가능. 깊이 밖 체결을 만들지 않고 비용 민감도 검사 |
| P2 | 100개 aggTrade 표본 기반 feature | 시간 길이가 시장 활동에 따라 변함. 시간 기반 feature와 warm-up 규칙 추가 |
| P2 | 상태 출력에 미실현 손익/equity/최대 낙폭 없음, 파일 로그 없음 | 정확한 평가 기준 시각과 함께 표시·저장 |
| P2 | 전체 종료가 24시간으로 제한되고 재접속/깨진 메시지/CLI 통합 테스트가 부족 | 서비스 실행 모드, 장시간 fault tests, 정상 종료 확인 필요 |
| P2 | 설치 후 hidden .pth 재발, 의존성 범위만 존재, CI 없음 | PYTHONPATH 실행 경로 문서화. 재현 설치·Python 지원 버전 CI 추가 |

P0는 현재 실자금 위험이 있다는 뜻이 아니라 ‘실거래를 구현/활성화하기 전 통과할 조건’이다.
reduce-only는 최신 호가가 있는 동안 market 피드 없이 동작하지만, 반복 market 연결 실패로
collector 전체가 종료되면 더 이상 청산할 수 없다. 이는 아직 긴급 청산 서비스가 아니다.

## 문서 정정

- ‘위험 관리 완료’ 대신 신규 매수의 제한적 검사로 표현한다.
- `kill_file`은 신규 진입 차단이며 자동 청산이 아니다.
- `hold_seconds`는 체결 시점이 아니라 매수 요청 시점에서 센다.
- 실현 손익 변화 + 전체 미실현 손익이라는 현재 기준을 정확한 일일 equity 손익과 구분한다.
- 로그 디렉터리는 자리만 있으며 시스템 로그는 터미널 출력이다.
- 기존 연결 smoke 기록은 과거 검증 결과로 유지한다. 이번 변경 후 live 재검증 결과로 표시하지 않는다.
- 실험 전략/보유 주기/AI는 제안이며 아직 구현되거나 성과가 검증되지 않았다.
